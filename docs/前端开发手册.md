## 枚举值定义

### 枚举使用规范

#### 枚举格式对照

前端与后端枚举格式保持一致，API通信统一使用**小写下划线**格式：

| 场景 | 格式 | 示例 |
|------|------|------|
| TypeScript类型定义 | 大写下划线 | `'COMPUTER_VISION'` |
| API请求参数 | 小写下划线 | `direction=computer_vision` |
| API响应JSON | 小写下划线 | `"direction": "computer_vision"` |
| URL路径参数（slug） | 小写简写 | `/direction/cv` |

#### 前端枚举定义示例

```typescript
// TypeScript类型定义（大写下划线）
export type Direction = 'COMPUTER_VISION' | 'STRUCTURAL_DESIGN' | 'EMBEDDED';

// 枚举标签映射
export const DIRECTION_LABELS: Record<Direction, string> = {
  COMPUTER_VISION: '计算机视觉',
  STRUCTURAL_DESIGN: '结构设计',
  EMBEDDED: '嵌入式开发',
};

// slug映射（用于URL）
export const DIRECTION_SLUGS: Record<Direction, string> = {
  COMPUTER_VISION: 'cv',
  STRUCTURAL_DESIGN: 'struct',
  EMBEDDED: 'embed',
};
```

#### API请求示例

```typescript
// 正确：使用小写下划线格式
const response = await client.get('/members', {
  params: { direction: 'computer_vision' }
});

// 错误：不要使用大写格式
const response = await client.get('/members', {
  params: { direction: 'COMPUTER_VISION' }  // ❌ 错误
});
```

## 开发规范

### 命名规范

- **组件文件**: PascalCase（如 `MemberCard.tsx`）
- **样式文件**: camelCase 或 module.css（如 `styles.module.css`）
- **工具函数**: camelCase（如 `RoleUtils.ts`）
- **API服务**: camelCase + .service.ts（如 `auth.service.ts`）

### Server Component 与 ISR 规范

项目使用 Next.js App Router，页面默认为 Server Component。**所有从后端获取数据的 Server Component 页面必须配置 ISR（增量静态再生成）**，否则 build 后内容固定，后端数据变更无法反映到页面上。

#### ISR 配置要求

1. 每个有后端数据获取的页面必须设置 `export const revalidate`
2. `revalidate` **必须是静态数字字面量**，Next.js 不支持变量引用或表达式
3. 默认值为 `3600`（1 小时），可根据业务需求调整
4. 纯静态页面（无后端数据）和 `'use client'` 页面不需要配置

```typescript
// ✅ 正确：静态数字字面量
export const revalidate = 3600

// ❌ 错误：Next.js 不支持变量引用
import { ISR } from '@/config/isr'
export const revalidate = ISR.home  // 编译报错：Unsupported node type "MemberExpression"

// ❌ 错误：运行时表达式
export const revalidate = Number(process.env.REVALIDATE) || 3600  // 编译报错
```

#### 已配置 ISR 的页面

| 页面 | 路径 | revalidate | 说明 |
|------|------|-----------|------|
| 首页 | `(home)/page.tsx` | 3600 | 竞赛列表数据 |
| 竞赛列表 | `competitions/page.tsx` | 3600 | 竞赛数据 |
| 实验室环境 | `lab-environment/page.tsx` | 3600 | 场地 + 设备数据 |
| 方向详情 | `direction/[slug]/page.tsx` | 3600 | 学习路径数据 |

#### ISR 配置参考文件

`src/frontend/src/config/isr.ts` 记录了各页面的 revalidate 值作为文档参考。由于 Next.js 限制，实际值必须以字面量写在各页面文件中。

#### 新建页面检查清单

- 页面是否为 Server Component（没有 `'use client'`）？
- 页面是否从后端获取数据（有 `async` 函数调用 API）？
- 如果都是，**必须**添加 `export const revalidate = <秒数>`

### 组件开发

1. 使用函数组件和Hooks
2. 样式优先使用CSS Modules
3. 组件拆分遵循单一职责原则
4. 类型定义放在 `types/` 或 `apis/schema/` 目录

### API调用

1. 所有API调用通过 `apis/services/` 下的服务模块
2. 使用统一的 Axios 实例（`apis/client.ts`）
3. 错误处理统一在拦截器中处理

### 状态管理

1. 全局状态使用 Zustand
2. 认证状态在 `stores/authStore.ts`
3. 组件内部状态使用 React useState

## 文件上传对接

### 概述

改造后的文件上传采用**预签名 URL 直传 OSS** 模式，前端不再将文件二进制流发送到后端，而是分三步完成：

1. **prepare**：向后端申请上传凭证（预签名 URL + callbackToken）
2. **upload**：使用预签名 URL 直接将文件 PUT 到 OSS（MinIO / 阿里云 OSS）
3. **confirm**：上传成功后，携带 callbackToken 通知后端确认

### 三步上传流程

#### Step 1: Prepare（获取预签名上传凭证）

```typescript
// POST /api/v1/file/prepare-upload
// Content-Type: application/json

interface PrepareUploadRequest {
  type: 'AVATAR' | 'NORMAL_IMG' | 'ASSESSMENT_ATTACHMENT' | 'WORK' | 'QRCODE';
  contentType: string;      // 如 'image/jpeg'
  size: number;             // 文件大小（字节）
  md5: string;              // 文件 MD5（Base64 编码）
}

interface PrepareUploadResponse {
  fileId: number;
  uploadUrl: string;        // 直传 OSS 的预签名 PUT URL
  callbackToken: string;    // 后续 confirm 用凭证
  filename: string;
  type: FileType;
}
```

**调用示例**：

```typescript
async function prepareUpload(
  file: File,
  type: FileType
): Promise<PrepareUploadResponse> {
  const md5 = await computeMD5Base64(file); // 使用 spark-md5 等库计算

  const res = await fetch('/api/v1/file/prepare-upload', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'X-CSRF-Token': csrfToken, // 已登录用户需携带
    },
    credentials: 'include',
    body: JSON.stringify({
      type,
      contentType: file.type,
      size: file.size,
      md5,
    }),
  });

  if (!res.ok) throw new Error('Prepare upload failed');
  return res.json();
}
```

**权限说明**：

- `AVATAR`、`NORMAL_IMG`：允许未登录用户调用（用于报名表头像等场景）
- 其他类型（`WORK`、`ASSESSMENT_ATTACHMENT`、`QRCODE`）：需要登录
- 匿名调用有 IP 级限流（每 5 秒 1 次）

---

#### Step 2: Upload（直传 OSS）

拿到 `uploadUrl` 后，前端直接使用 HTTP PUT 将文件上传到该 URL，**不携带 Cookie**。

```typescript
async function uploadToOSS(
  file: File,
  uploadUrl: string
): Promise<void> {
  const res = await fetch(uploadUrl, {
    method: 'PUT',
    headers: {
      'Content-Type': file.type,
      // 'Content-Length': file.size.toString(), // 浏览器自动设置
    },
    body: file,
    // 注意：不能携带 Cookie 到 OSS 域名
    credentials: 'omit',
  });

  if (!res.ok) throw new Error('OSS upload failed');
}
```

**重要约束**：

- 必须使用 `PUT` 方法，不能使用 `POST`
- `Content-Type` 必须与 prepare 时传入的一致，否则 OSS 拒绝
- 上传域名是 OSS 域名（如 `http://localhost:9000` 或阿里云域名），不是后端 API 域名
- 预签名 URL 有效期 15 分钟，超时需重新 prepare

---

#### Step 3: Confirm（通知后端确认）

OSS 上传成功后，调用 confirm 接口通知后端校验文件并完成入库。

```typescript
// POST /api/v1/file/confirm-upload
// Content-Type: application/json

interface ConfirmUploadRequest {
  fileId: number;
  callbackToken: string;
}

interface ConfirmUploadResponse {
  fileId: number;
  filename: string;
  type: FileType;
  status: 'ACTIVE' | 'REJECTED';
}
```

**调用示例**：

```typescript
async function confirmUpload(
  fileId: number,
  callbackToken: string
): Promise<ConfirmUploadResponse> {
  const res = await fetch('/api/v1/file/confirm-upload', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'X-CSRF-Token': csrfToken,
    },
    credentials: 'include',
    body: JSON.stringify({ fileId, callbackToken }),
  });

  if (!res.ok) throw new Error('Confirm upload failed');
  return res.json();
}
```

**确认结果**：

- `status === 'ACTIVE'`：上传成功，文件可用
- `status === 'REJECTED'`：校验失败（MD5 不匹配或魔数异常），后端已自动清理 OSS 对象，前端应提示用户重新上传

---

### 完整封装示例

```typescript
export async function uploadFile(
  file: File,
  type: FileType
): Promise<{ fileId: number; filename: string }> {
  // 1. Prepare
  const prepared = await prepareUpload(file, type);

  // 2. Upload to OSS
  await uploadToOSS(file, prepared.uploadUrl);

  // 3. Confirm
  const confirmed = await confirmUpload(prepared.fileId, prepared.callbackToken);

  if (confirmed.status === 'REJECTED') {
    throw new Error('文件校验失败，请重新上传');
  }

  return { fileId: confirmed.fileId, filename: confirmed.filename };
}
```

### 下载接口变化

#### 单文件下载

`GET /api/v1/file/download/{fileId}` 现在返回 **302 Redirect**，前端需跟随重定向：

```typescript
// 浏览器会自动跟随 302，直接设置 href 即可
window.location.href = `/api/v1/file/download/${fileId}`;

// 或使用 fetch（需处理重定向）
const res = await fetch(`/api/v1/file/download/${fileId}`, {
  credentials: 'include',
  redirect: 'follow',
});
```

#### 批量下载

`GET /api/v1/file/download/batch?fileIds=1,2,3` 返回流式 ZIP，浏览器自动触发下载：

```typescript
window.location.href = `/api/v1/file/download/batch?fileIds=${fileIds.join(',')}`;
```

---

### 注意事项

1. **MD5 计算**：prepare 前必须计算完整文件的 MD5（Base64 编码），后端用于校验文件完整性。
2. **进度监控**：直传 OSS 时可用 `XMLHttpRequest` 替代 `fetch` 以获取上传进度。
3. **断网恢复**：若 Step 2 上传失败（网络中断），可直接重试同一个 `uploadUrl`（在有效期内）；若 URL 过期，需重新执行 Step 1。
4. **旧接口兼容**：`POST /api/v1/file/upload` 仍可用但已标记 `@Deprecated`，建议新功能统一迁移到三步流程。
