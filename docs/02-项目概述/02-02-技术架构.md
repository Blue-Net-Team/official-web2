## DDD 四层架构

后端采用 DDD 分层架构：

```
api/              # API 层：Controller、DTO、Converter
application/      # 应用层：Service、Command、Result、编排
domain/           # 领域层：Entity、Repository 接口、DomainService、VO
infrastructure/   # 基础设施层：RepositoryImpl、Mapper、Config、外部客户端
```

层间返回类型约定见 [03-05-层间约定](../03-开发指南/03-05-层间约定.md)。

## 运行时架构

下图展示服务器运行时架构与核心通信链路（不含 CI/CD，CI/CD 详见 [04-03-CI-CD自动部署](../04-运维部署/04-03-CI-CD自动部署.md)）。AI 服务请求在生产环境通过 Nginx 反向代理到 `/ai/v1`，与 `/api/v1` 统一入口；本地开发可按配置直连 `ai-service:8000`。

```mermaid
flowchart TB
    subgraph External ["外部用户与服务"]
        Browser["用户浏览器"]
        GitHubOAuth["GitHub OAuth"]
        GitHubApp["GitHub App<br/>Bug 报告同步"]
        SMTP["SMTP 邮件服务"]
        ExtAI["外部 AI / Embedding API<br/>(SiliconFlow / DeepSeek / Ollama)"]
    end

    subgraph Runtime ["服务器运行时（Docker Compose）"]
        Nginx["Nginx 反向代理<br/>:80 / :443"]
        Frontend["Frontend<br/>Next.js :3000"]
        Backend["API Service<br/>Spring Boot :8080"]
        Judge["Judge Service<br/>:8090"]
        AI["AI Service<br/>Python :8000"]

        subgraph Infra ["基础设施"]
            DB["PostgreSQL<br/>pgvector :5432"]
            Redis["Redis :6379"]
            RabbitMQ["RabbitMQ<br/>:5672 / :15672"]
            MinIO["MinIO 对象存储<br/>:9000"]
        end
    end

    Browser -->|"HTTPS 页面请求"| Nginx
    Nginx -->|"转发 :3000"| Frontend
    Browser -->|"CSR /api/v1"| Nginx
    Nginx -->|"转发 :8080"| Backend
    Browser -->|"预签名 URL 直传 :7000"| MinIO
    Browser -->|"/ai/v1"| Nginx
    Nginx -->|"转发 :8000"| AI

    Frontend -->|"SSR 服务端请求"| Backend

    Backend -->|"SQL"| DB
    Backend -->|"缓存"| Redis
    Backend -->|"判题任务队列"| RabbitMQ
    Backend -->|"文件存取"| MinIO
    Backend -->|"OAuth 回调"| GitHubOAuth
    Backend -->|"创建 Issue"| GitHubApp
    Backend -->|"发送邮件"| SMTP

    Judge -->|"消费任务"| RabbitMQ
    Judge -->|"读写用例/结果"| MinIO
    Judge -->|"持久化"| DB

    AI -->|"向量检索"| DB
    AI -->|"后端接口"| Backend
    AI -->|"Embedding / LLM / Reranker"| ExtAI
```
