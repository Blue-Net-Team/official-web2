# ADR 0001: 采用 DDD 四层架构

## 状态

已采纳

## 背景

BlueNet 是一个长期演进的团队管理平台，业务领域涵盖报名、考核、成员、权限、文件、算法判题等。随着功能增长，传统的 MVC 分层导致 Service 层臃肿、业务逻辑与数据访问耦合、测试困难。

## 决策

后端采用 DDD（领域驱动设计）四层架构：

| 层级 | 职责 | 包路径 |
|------|------|--------|
| API 层 | 接收 HTTP 请求、参数校验、DTO 转换、返回 ResponseMessage | `com.bluenet.web.api.*` |
| 应用层 | 编排用例、事务边界、调用 DomainService 与 Repository | `com.bluenet.web.application.*` |
| 领域层 | 业务规则、实体行为、Repository 接口、领域事件 | `com.bluenet.web.domain.*` |
| 基础设施层 | Repository 实现、Mapper、外部服务客户端、配置 | `com.bluenet.web.infrastructure.*` |

## 后果

### 正面

- 业务规则集中在领域层，便于单元测试。
- 层间依赖单向，领域层不依赖 API / 基础设施。
- 便于替换基础设施（如从 MinIO 切换到阿里云 OSS）。

### 负面

- 初学者需要理解 DDD 分层与返回类型约定。
- 简单 CRUD 也需要遵循分层，增加了少量样板代码。
