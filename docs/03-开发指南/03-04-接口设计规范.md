# 接口设计规范

## REST 接口前缀

所有 REST 接口统一以 `/api/v1` 为前缀。

主要接口模块如下：

| 模块 | 路径 | 说明 |
|------|------|------|
| 认证 | /auth | 登录、登出 |
| 用户 | /user | 用户信息管理 |
| 消息 | /message | 验证码、消息模板 |
| 文件 | /file | 文件上传下载（预签名直传） |
| 介绍 | /intro | 竞赛、成就展示 |
| 报名 | /enroll | 报名管理 |
| 考核 | /assessment | 考核时间、题目、答案、评判、决策、会话、统计 |
| 考核队伍 | /assessment-teams | 组队答题管理 |
| 算法判题 | /algorithm-judge | 算法题运行、提交、轮询 |
| Bug 报告 | /bug-reports | Bug 提交与跟踪 |
| 审计 | /audit | 日志查询 |

## 统一响应 ResponseMessage<T>

所有 REST 接口返回值必须使用 `ResponseMessage<T>` 统一包装，确保前端能够以一致的格式处理成功与失败结果。

- 成功响应：通过 `ResponseMessage.success(data)` 构造。
- 失败响应：由 `GlobalExceptionHandler` 统一捕获领域异常后构造；Controller 层禁止自行 try-catch 返回 `ResponseMessage.error()`。

## 统一异常处理

项目使用统一的领域异常体系，对应常见的 HTTP 状态码：

| 异常类型 | HTTP 状态码 | 使用场景 |
|----------|-------------|----------|
| `BadRequest` | 400 | 请求参数错误、业务校验失败 |
| `Unauthorized` | 401 | 未登录或认证信息无效 |
| `Forbidden` | 403 | 已登录但无权限访问 |
| `DataNotFound` | 404 | 请求的数据不存在 |
| `DataConflict` | 409 | 数据冲突，如重复提交、唯一约束冲突 |

Controller 层方法禁止自行 try-catch 并返回 `ResponseMessage.error()`。所有业务异常统一交由 `@ControllerAdvice`（`GlobalExceptionHandler`）处理。仅允许在需要返回非 200 HTTP 状态码的场景（如登录接口返回 401）中使用 try-catch + `ResponseEntity`。

## 分页接口规范

**必须使用 `PageDTO<T>` 而非 Spring Data 的 `Page<T>`。**

Spring Data 的 `Page<T>` 序列化后的字段与前端 `PageDTO<T>` 接口定义不匹配，所有分页接口必须返回 `PageDTO<T>`。

### Controller 层示例

```java
// ✅ 正确
@GetMapping
public ResponseMessage<PageDTO<AchievementDTO>> getAchievements(
        @RequestParam(defaultValue = "0") Integer page,
        @RequestParam(defaultValue = "12") Integer size) {
    return ResponseMessage.success(achievementService.getAchievements(page, size, ...));
}

// ❌ 错误 - Spring Data Page 序列化格式与前端不兼容
@GetMapping
public ResponseMessage<Page<AchievementDTO>> getAchievements(...) {
    return ResponseMessage.success(achievementService.getAchievements(...));
}
```

### Service 层示例

```java
@Override
public PageDTO<AchievementDTO> getAchievements(Integer page, Integer size, ...) {
    // 1. 创建分页请求
    Pageable pageable = PageRequest.of(page, size);
    
    // 2. 执行分页查询
    Page<AchievementReadModel> readModelPage = repository.findWithFilter(..., pageable);
    
    // 3. 转换为 DTO 分页
    Page<AchievementDTO> dtoPage = readModelPage.map(converter::convertToDTO);
    
    // 4. 关键：转换为 PageDTO
    return PageDTO.from(dtoPage);
}
```

### 前端对应类型

```typescript
// 前端 PageDTO 接口定义
interface PageDTO<T> {
  content: T[]              // 内容列表
  totalElements: number     // 总元素数
  totalPages: number        // 总页数
  number: number            // 当前页码（从 0 开始）
  size: number              // 每页大小
  numberOfElements: number  // 当前页元素数
  first: boolean            // 是否第一页
  last: boolean             // 是否最后一页
  empty: boolean            // 是否为空
}
```

### 注意事项

1. Controller 返回类型必须是 `ResponseMessage<PageDTO<XxxDTO>>`。
2. Service 层使用 `PageDTO.from(dtoPage)` 进行转换。
3. 分页参数：`page` 从 0 开始，`size` 默认值根据业务场景设置。

## 审计日志

所有操作记录审计日志：

- 操作人、操作时间
- 请求参数（JSON 格式）
- 客户端 IP、User-Agent
- 操作结果

系统通过 `tb_audit` 表统一记录操作审计日志，详细数据库规范见 [03-06-数据库规范](./03-06-数据库规范.md)。
