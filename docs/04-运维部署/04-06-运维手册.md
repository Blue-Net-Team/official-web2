## 日志查看

### 1. 后端服务日志（api-service）

```bash
# 进入部署目录
cd [填写]

# 实时查看日志
docker compose logs -f api-service

# 查看最近 100 行
docker compose logs --tail=100 api-service

# 查看指定时间范围（如过去 1 小时）
docker compose logs --since=1h api-service
```


### 3. AI 服务日志（ai-service）

```bash
ssh -p [填写] [填写]@[填写]

docker compose logs -f ai-service
```

### 4. 前端服务日志（frontend）

```bash
cd [填写]
docker compose logs -f frontend
```

### 5. 基础设施日志

```bash
cd [填写]

# 数据库
docker compose logs -f database

# Redis
docker compose logs -f redis

# RabbitMQ
docker compose logs -f rabbitmq

# MinIO
docker compose logs -f minio
```

### 6. 日志持久化建议

- 生产环境建议启用 Docker 日志驱动（如 `json-file`）并限制单容器日志大小：
  ```yaml
  logging:
    driver: "json-file"
    options:
      max-size: "100m"
      max-file: "5"
  ```
- 关键业务日志建议接入外部日志平台（如 Loki / ELK / SLS）以便检索。

## 健康检查

### 1. 后端 API 健康检查

```bash
curl -sfL http://[填写]:8080/api/v1/health | jq .
```

预期响应包含 `"code":200`。

### 2. 判题服务健康检查

```bash
curl -sfL http://[填写]:8090/api/v1/judge/health | jq .
```

预期响应包含 `"status":"UP"`。

### 3. AI 服务健康检查

```bash
curl -sfL http://[填写]:[填写]/ai/v1/health | jq .
```

预期响应包含 `"status":"ok"`。

### 4. 前端页面检查

```bash
curl -sfL -I http://[填写]:3000
```

预期返回 HTTP 200。

### 5. 基础设施检查

```bash
cd [填写]

# 查看容器运行状态
docker compose ps

# 数据库连接测试
docker compose exec database psql -U postgres -d blue_net -c "SELECT 1;"

# Redis 连接测试
docker compose exec redis redis-cli ping

# RabbitMQ 管理界面
# 浏览器访问 http://[填写]:15672

# MinIO 控制台
# 浏览器访问 http://[填写]:7001
```

### 6. 自动化健康检查脚本示例

```bash
#!/bin/bash
set -e

API_URL="http://[填写]:8080/api/v1/health"
JUDGE_URL="http://[填写]:8090/api/v1/judge/health"
AI_URL="http://[填写]:[填写]/ai/v1/health"

for url in "$API_URL" "$JUDGE_URL" "$AI_URL"; do
  echo "Checking $url ..."
  curl -sfL "$url" > /dev/null || { echo "❌ Health check failed: $url"; exit 1; }
done

echo "✅ All health checks passed"
```

## 备份策略

### 1. 数据库备份

建议每日自动备份 PostgreSQL 数据：

```bash
#!/bin/bash
BACKUP_DIR="/backup/bluenet/database"
DATE=$(date +%Y%m%d_%H%M%S)
mkdir -p "$BACKUP_DIR"

cd [填写]
docker compose exec -T database pg_dump -U postgres -d blue_net | gzip > "$BACKUP_DIR/blue_net_$DATE.sql.gz"

# 保留最近 7 天备份
find "$BACKUP_DIR" -name "blue_net_*.sql.gz" -mtime +7 -delete
```

### 2. 文件备份

MinIO 中的对象存储数据需定期备份：

```bash
#!/bin/bash
BACKUP_DIR="/backup/bluenet/minio"
DATE=$(date +%Y%m%d_%H%M%S)
mkdir -p "$BACKUP_DIR"

# 如使用 Docker Volume
docker run --rm -v bluenet_minio_data:/data -v "$BACKUP_DIR:/backup" alpine tar czf "/backup/minio_$DATE.tar.gz" -C /data .

# 保留最近 7 天备份
find "$BACKUP_DIR" -name "minio_*.tar.gz" -mtime +7 -delete
```

### 3. 配置备份

至少包含以下内容：

- `.env` 环境变量文件
- `docker-compose.yml`
- Nginx 配置文件
- SSL 证书与私钥

建议将配置纳入 Git 版本管理（注意不提交敏感信息），或使用配置管理工具（如 Ansible）。

### 4. 备份验证

定期执行恢复演练：

```bash
# 测试数据库恢复
gunzip < /backup/bluenet/database/blue_net_YYYYMMDD_HHMMSS.sql.gz | docker compose exec -T database psql -U postgres -d blue_net_test
```

### 1. 关键监控指标

| 指标 | 告警阈值建议 | 说明 |
|------|-------------|------|
| 容器 CPU 使用率 | > 80% 持续 5 分钟 | `docker stats` 或 cAdvisor |
| 容器内存使用率 | > 85% 持续 5 分钟 | 内存泄漏预警 |

## 常见故障排查

### 1. 服务无法启动

**现象**：`docker compose ps` 显示容器 Exited 或 Restarting。

**排查步骤**：

```bash
# 1. 查看最后 50 行日志
docker compose logs --tail=50 [service-name]

# 2. 检查环境变量是否完整
docker compose config

# 3. 检查端口占用
ss -tlnp | grep -E '3000|8080|8090|15432|5672|15672|7000|7001'

# 4. 检查磁盘空间
df -h

# 5. 检查容器资源限制
docker inspect [container-id] | grep -A 20 "Resources"
```

### 2. 数据库连接失败

**现象**：后端日志出现 `Connection refused` 或 `FATAL: password authentication failed`。

**排查步骤**：

```bash
# 1. 检查数据库容器状态
docker compose ps database

# 2. 确认密码正确
cat .env | grep DB_PASSWORD

# 3. 进入数据库测试
docker compose exec database psql -U postgres -d blue_net -c "SELECT 1;"

# 4. 检查网络连通性
docker compose exec api-service ping database
```

### 3. 前端请求后端报 502/504

**现象**：前端页面可打开，但 API 请求失败。

**排查步骤**：

```bash
# 1. 检查后端服务是否健康
curl http://[填写]:8080/api/v1/health

# 2. 检查 Nginx 错误日志
tail -f /var/log/nginx/error.log

# 3. 检查 Nginx upstream 配置
nginx -t

# 4. 检查后端容器资源
docker stats api-service
```

### 4. 文件上传失败

**现象**：上传文件时报错或预签名 URL 无法访问。

**排查步骤**：

```bash
# 1. 检查 MinIO 容器状态
docker compose ps minio

# 2. 检查 MinIO 日志
docker compose logs minio

# 3. 确认 MINIO_PUBLIC_URL 配置正确
cat .env | grep MINIO

# 4. 测试 bucket 访问
mc alias set local http://localhost:7000 [access-key] [secret-key]
mc ls local/[bucket-name]
```

### 5. 判题服务无响应

**现象**：提交算法题后长时间无结果。

**排查步骤**：

```bash
# 1. 检查判题服务健康状态
curl http://[填写]:8090/api/v1/judge/health

# 2. 检查 RabbitMQ 队列积压
# 浏览器访问 http://[填写]:15672
# 查看 queues 中是否有大量未消费消息

# 3. 检查 judge-service 日志
docker compose logs -f judge-service
```

### 6. AI 客服服务异常

**现象**：AI 客服无法回复或响应超时。

**排查步骤**：

```bash
# 1. 检查 AI 服务健康状态
curl http://[填写]:[填写]/ai/v1/health

# 2. 检查 AI 服务日志
docker compose logs -f ai-service
```

## 回滚流程

### 1. 镜像回滚

当新版本部署出现问题时，可回滚到上一个稳定镜像：

```bash
cd [填写]

# 查看本地可用镜像
docker images | grep bluenet

# 回滚到指定镜像版本
API_SERVICE_IMAGE=ghcr.io/[填写]/bluenet-api-service:[填写] \
FRONTEND_IMAGE=ghcr.io/[填写]/bluenet-frontend:[填写] \
JUDGE_IMAGE=ghcr.io/[填写]/bluenet-judge-service:[填写] \
AI_SERVICE_IMAGE=ghcr.io/[填写]/bluenet-ai-service:[填写] \
docker compose --profile full up -d --remove-orphans
```

### 2. 数据库回滚

**注意**：数据库回滚风险较高，操作前务必备份。

```bash
# 1. 先备份当前数据库
docker compose exec -T database pg_dump -U postgres -d blue_net | gzip > rollback_backup_$(date +%Y%m%d_%H%M%S).sql.gz

# 2. 停止后端服务
docker compose stop api-service

# 3. 恢复目标备份
gunzip < [backup-file].sql.gz | docker compose exec -T database psql -U postgres -d blue_net

# 4. 重新启动服务
docker compose up -d api-service
```

### 3. 配置回滚

```bash
cd [填写]

# 从 Git 历史恢复配置
git checkout [commit-hash] -- docker-compose.yml .env

# 重新加载配置
docker compose --profile full up -d --remove-orphans
```
