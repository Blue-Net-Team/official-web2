# Git 提交信息规范

## 格式

```
type(optional): description
```

## 提交类型

| 类型       | 说明                      |
| ---------- | ------------------------- |
| `feat`     | 新功能                    |
| `fix`      | 修复 Bug                  |
| `docs`     | 文档更新                  |
| `style`    | 代码格式（不影响功能）    |
| `refactor` | 重构                      |
| `test`     | 测试相关                  |
| `chore`    | 构建/工具变动             |
| `ci`       | CI/CD 配置变动            |
| `build`    | 构建系统变动              |
| `revert`   | 回滚提交                  |

## 作用域（可选）

根据修改的内容选择适当的作用域，包括但不限于，也可以使用相关的模块名：

- `API` - 后端接口
- `Auth` - 认证授权
- `Test` - 测试代码
- `Config` - 配置相关
- `Deps` - 依赖更新

## 规则

1. 冒号后必须有一个空格
2. 描述至少 5 个字符
3. 描述不建议以句号结尾
4. 使用中文描述
5. 描述应简洁明了，说明改动的目的

## 示例

```
feat: 添加用户登录功能
feat(UI): 添加登录表单组件
```

## 多行提交

当需要详细说明时，使用多行格式：

```
feat: 添加用户登录功能

- 添加表单验证逻辑
- 集成 JWT 认证
```

## 注意事项

- 一次提交只包含一个逻辑改动
- 避免提交信息过于笼统（如"修改代码"、"更新"）
- 修复 Bug 时说明修复的问题，而非修改的内容
