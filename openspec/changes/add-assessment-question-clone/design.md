## Context

考题通过 `assessment_time_id` 归属于考核时间，同一考核时间内的题号由应用层保证唯一。当前管理端已支持按方向和考核时间筛选题目，以及创建、编辑、删除单题，但没有复制能力。算法题还在独立判题配置中保存 generator、标准解、测试用例生成参数和 benchmark 参数，相关源码及生成数据位于判题专用 OSS。

判题资产当前使用 `questions/{questionId}/current/` 命名空间；测试数据文件名包含内容哈希，但完整对象键仍包含题目 ID。重新生成测试数据会删除当前题目的旧对象，删除题目也会清理当前题目的资产前缀。因此，克隆若直接复用源题对象键，会在源题删除或重新生成时产生悬挂引用。

本变更遵循现有 DDD 分层、统一 `ResponseMessage`、`@RequiresPermission` 和前端 API service 约定，不改变考生作答、评分或 Judge Service 的既有工作流程。

## Goals / Non-Goals

**Goals:**

- 提供单题克隆接口和管理端入口，将题目定义复制到同方向的另一考核时间。
- 支持目标题号默认最大题号加一并允许修改，后端最终校验题号冲突。
- 新题目与源题在数据库内容、后续编辑和判题资产删除生命周期上相互独立。
- 算法题副本携带可重新生成测试数据的完整源码配置，并明确回到 `DRAFT`。
- 将方向访问策略与复制编排分离，避免未来开放跨方向时重写复制和资产隔离逻辑。

**Non-Goals:**

- 不支持多题批量克隆、整卷克隆或克隆时新建考核时间。
- 不开放跨方向克隆，不调整现有普通附件的跨方向授权模型。
- 不复制作答、提交历史、评分、评语、统计、会话、队伍或其他考生运行数据。
- 不复制已生成测试数据、benchmark 结果或语言资源限制，不在克隆后自动生成或测速。
- 不建立题库、源题血缘、跨题同步或共享判题资产引用计数机制。
- 不处理既有考题在考核开始后仍可编辑的管理规则。

## Decisions

### 1. 使用单题克隆命令和独立管理接口

新增 `POST /api/v1/admin/assessment-questions/{id}/clone`，请求体包含：

- `targetAssessmentTimeId`: 必填，目标考核时间 ID。
- `targetQuestionNo`: 必填且大于 0，目标题号。

接口使用 `@RequiresPermission(name = "克隆考题", value = "assessment-question:clone", access = PROTECTED)`，返回 `ResponseMessage<AssessmentQuestionDTO>`，其中 DTO 是新题目。请求转换器将路径中的源题 ID 合并为 `CloneAssessmentQuestionCommand`，应用服务签名携带当前 `userId`，与考核时间管理接口的用户上下文方式一致。

不采用“前端读取源题后调用现有创建接口”的方案，因为该方案会暴露并重组完整题目与判题源码、难以保证算法配置和 OSS 写入的一致性，也无法可靠隔离方向权限。

### 2. 复制编排与方向策略分离

`AssessmentQuestionAppService.cloneQuestion` 负责事务编排：

1. 查询当前用户、源题、源考核时间和目标考核时间，任一不存在则返回对应不存在错误。
2. 拒绝源、目标考核时间相同，以及目标题号冲突。
3. 调用独立的方向访问校验，通过后再执行复制。
4. 深复制题面内容，使用目标考核时间和目标题号创建新题目并保存，取得新题目 ID。
5. 若源题为算法题且存在判题配置，则复制源码配置到目标题目；不存在配置时，目标同样保持未配置。
6. 返回新题目结果，不修改源题。

方向校验作为独立应用策略/私有策略组件处理，不让核心复制逻辑依赖年级或方向相等：

- `DIRECTION_ADMIN` 的源和目标都必须属于其本人方向。
- `SUPER_ADMIN` 可在同一技术方向内克隆，也可在两个全局考核之间克隆。
- 源、目标方向不一致时拒绝；年级和轮次可以不同。
- 其他角色即使获得接口权限，也不能绕过该管理边界。

未来跨方向只需调整该策略并同时完成普通附件授权设计，不改变克隆命令、题目复制或判题资产所有权。

### 3. 深复制题目定义，不引入源题关联

新记录复制 `questionType`、`title`、`content`、`attachmentId` 和 `score`，使用新的 `id`、`assessmentTimeId` 和请求指定的 `questionNo`。题面中的选项、正确答案、样例、运行用例和 `starterCode` 都属于题目定义，必须完整复制。

`QuestionContent` 含可变列表和 Map，复制时必须通过专门复制方法或可靠的多态 JSON 深复制获得独立对象，不能把源对象及其嵌套集合直接共享给副本。克隆后调用既有内容归一化和算法题校验，避免复制逻辑绕过创建规则。

不增加 `sourceQuestionId`，不做数据库迁移。普通附件在同方向场景仅复用 `attachmentId`；更换源题或副本附件仍只修改各自题目记录。

### 4. 复用判题配置应用服务重建目标配置

算法题不直接复制配置表行或对象键。克隆编排通过 `JudgeProblemConfigAdminService` 读取源配置的完整管理视图，再转换为目标 `UpsertCommand` 并调用现有 `upsert`：

- 复制 generator 语言与源码、主标准解语言、全部标准解源码、测试用例生成参数和 benchmark 参数。
- 现有 `upsert` 为目标新题目 ID、新配置 ID 创建配置记录，重新写入 generator/标准解并生成包含目标 ID 的 manifest。
- 新配置按既有工厂逻辑从 `DRAFT` 开始，标准解 benchmark 状态重新从 `PENDING` 开始。
- 不调用 `requestGeneration`，不复制生成测试用例记录和语言资源限制。

若源算法题没有配置，允许只克隆题面，目标保持未配置；若源配置存在但 generator 或标准解源码缺失/为空，则克隆失败，不得利用现有读取兜底静默生成空源码配置。

该方案复用已有 manifest 和对象键生成规则，优于直接复制数据库行，也优于让目标引用源对象键。

### 5. 判题资产按目标题目独占，禁止跨题共享可变对象键

复制后的完整对象键必须位于目标命名空间：

```text
源题：questions/{sourceQuestionId}/current/...
副本：questions/{targetQuestionId}/current/...
```

即使源码或未来重新生成的 `.in/.out` 内容哈希相同，也只能表示内容相同，不能据此复用其他题目的对象键。manifest 必须重建，因为其内容包含 `questionId` 和 `configId`。

删除或重新生成源题只能清理源题命名空间，目标配置不得引用其中的任何对象。未来若需要去重，必须另立共享资产、引用计数和垃圾回收设计；本变更不引入该复杂度。

### 6. 前端使用现有分页数据计算默认目标题号

在考题表格操作中增加“克隆”按钮，打开独立弹窗。目标下拉仅展示当前方向下、排除源考核时间的场次，并显示方向、轮次、年级和起止时间以区分场次。

选择目标后，通过现有管理端题目分页接口确定最后一页，读取按 `questionNo ASC` 排序的最后一条记录，计算最大题号加一；空目标默认题为 1。计算结果填入可编辑的 `InputNumber`，避免通过固定大页Size猜测最大题号。

提交后仍以后端冲突校验为准；并发导致冲突时提示用户并允许重新计算/修改。成功后关闭弹窗并刷新源列表，提示克隆成功，不强制跳转；可提供查看目标场次的后续增强，但不作为本期要求。

### 7. 失败必须不影响源题，且不留下可引用的半成品副本

数据库操作在同一事务中完成，任何校验、配置复制或 OSS 写入异常都不得保留可查询的目标半成品。若目标 OSS 已写入后事务失败，按目标题目前缀进行尽力清理；清理失败只可能留下无引用的目标孤立对象，不得清理或改写源题资产。

## Risks / Trade-offs

- [源码和配置分别复制会增加 OSS 存储] → 换取明确所有权和安全删除；不在本期引入引用计数、共享资产和异步 GC。
- [算法副本不会立即可判题] → 在交互与接口文档中明确 `DRAFT` 状态，管理员需重新生成、测速和确认限制；避免复制陈旧运行结果。
- [相同 generator 仍可能因随机性产生不同测试数据] → 不承诺副本与源题测试数据一致；以目标重新生成的数据为准。
- [目标题号在弹窗计算后可能被其他管理员占用] → 后端提交时再次检查并返回 409，前端保留弹窗供修改。
- [OSS 与数据库不存在跨系统原子事务] → 数据库回滚加目标前缀尽力清理，并保证任何失败路径都不触碰源对象。
- [当前普通附件授权通过关联题目推断] → 本期只允许同方向复用附件；未来跨方向必须先扩展授权模型或复制附件，不能仅放开方向判断。
- [新权限扫描后未分配给方向管理员] → 部署后通过既有角色权限管理为需要的角色授予 `assessment-question:clone`，并在端到端验收中确认。

## Migration Plan

1. 以新增接口、权限和前端入口的方式发布，无数据库结构迁移、无历史数据回填。
2. 启动后确认权限扫描无重复值，并为方向管理员等目标角色配置新权限。
3. 使用普通题和算法题各执行一次跨年级克隆，再验证目标重新生成及源题删除后的资产可用性。
4. 回滚时移除前端入口和新接口即可；已经创建的副本按普通独立题目保留或手动删除，无需反向数据迁移。

## Open Questions

无。跨方向克隆、批量/整卷克隆和“复制全部测试数据后立即可用”均留待后续独立变更。
