## ADDED Requirements

### Requirement: 隔离环境的可重复重置

压测工具 SHALL 提供 PostgreSQL、Redis、RabbitMQ、MinIO、API 与 Judge 的隔离环境重置流程，并在空数据库上重启 API 以触发 Flyway 和系统用户初始化。业务数据清理与初始化 MUST NOT 依赖手写 SQL，重置入口 MUST 要求专用环境标识和显式破坏性操作确认，并拒绝可识别的生产或共享环境目标。

#### Scenario: 操作者重置专用压测环境

- **WHEN** 操作者对专用压测环境提供明确的破坏性操作确认并执行重置
- **THEN** 工具清除上一轮数据库、缓存、队列和对象存储状态，重启并等待服务健康，且 API 自动完成数据库迁移和系统管理员初始化

#### Scenario: 重置目标缺少安全确认

- **WHEN** 重置目标不是受支持的隔离环境或操作者未提供明确确认
- **THEN** 工具 MUST 在执行任何删除前失败并说明原因

### Requirement: 通过业务 API 初始化测试上下文

压测工具 SHALL 使用系统管理员正常登录并调用现有业务 API 创建学院、测试考生、有效考核轮次、文件上传题、可配置数量的多道 Python 算法题及每题完整判题配置，且 SHALL 向场景提供包含动态实体 ID 集合、用户池和固定负载参数的测试上下文。初始化 MUST NOT 依赖数据库中已有的业务 ID 或硬编码生产账号。

#### Scenario: 初始化三个场景所需数据

- **WHEN** 压测环境健康且系统管理员可以正常登录
- **THEN** 工具通过业务 API 创建全部基础数据，等待算法测试数据生成等异步初始化完成，并返回可供 k6 场景使用的统一测试上下文

#### Scenario: 初始化未形成可运行环境

- **WHEN** 任一必要数据创建失败、异步初始化未完成或单用户预跑无法触达目标业务
- **THEN** 工具 MUST 中止加压并报告失败阶段，MUST NOT 将后续失败请求计为有效业务负载

### Requirement: 隔离测试用户和认证会话

文件考核与算法判题场景 SHALL 维护测试用户池，并将用户与 VU 稳定一对一分配。用户池容量 MUST 覆盖场景最大 VU 数；每个 VU MUST 正常登录、复用自己的 Cookie/CSRF 会话，并在所有要求的状态修改请求中携带正确 CSRF Token。工具 MUST NOT 增加或使用 JWT 绕过机制。

#### Scenario: 用户池覆盖最大并发

- **WHEN** 多个认证 VU 开始执行压测
- **THEN** 每个 VU 使用不同测试考生，首次迭代登录后复用会话，不会因其他 VU 登录同账号而撤销自身 Token

#### Scenario: 用户池容量不足

- **WHEN** 测试用户数小于场景配置允许的最大 VU 数
- **THEN** 工具 MUST 在正式加压前失败，MUST NOT 通过多 VU 共享账号继续执行

### Requirement: 报名新建负载

报名场景 SHALL 通过 `POST /api/v1/enrollments` 生成可配置的新建报名负载，并为每条新报名使用全局唯一且符合约束的学号。首轮场景 MUST 只将 HTTP 201 且业务成功的新建报名计为有效样本，不得将冲突、覆盖更新或参数错误计为成功。

#### Scenario: 多个虚拟用户执行新报名

- **WHEN** 报名场景按配置的速率和总量运行
- **THEN** 每次有效迭代提交不同学号并创建独立报名记录，结果分别报告尝试数、新建成功数、冲突数、错误率和延迟

### Requirement: 文件考核完整上传负载

文件考核场景 SHALL 对每个样本执行 prepare-upload、通过预签名 URL 直传 MinIO、confirm-upload 和以本人身份提交或更新文件答案的完整链路。基线 SHALL 在正式 5 分钟负载窗口内均匀启动 200 个人次，即平均 40 人次/分钟，并在登录完成后开始计时；只有完整成功闭环 MUST 计入 200 个有效人次目标。文件类型、大小和内容生成方式 MUST 在实验中固定并记录，预签名直传与 API 请求 MUST 分别计量。

#### Scenario: 考生在基线窗口完成文件答案提交

- **WHEN** 认证 VU 在 5 分钟正式负载窗口内使用初始化生成的文件上传题执行一次迭代
- **THEN** 工具完成预签名准备、真实文件 PUT、上传确认和答案提交或更新，仅在所有步骤成功后记录一个有效人次，并使基线计划总共启动 200 个流程

#### Scenario: 文件链路中途失败

- **WHEN** 预签名准备、MinIO 直传、上传确认或答案提交任一步骤失败
- **THEN** 工具标记该样本失败、记录具体阶段，MUST NOT 继续将未上传文件提交为有效答案

### Requirement: 多道 Python 算法题的运行与正式提交闭环负载

算法场景 SHALL 初始化可配置数量的多道算法题，按固定且可记录的规则分配题目，并同时覆盖不计分运行 API 与正式提交 API。每道题 SHALL 使用固定且确定性的 Python 源码和完整判题资产，两类操作 MUST 分别经 RabbitMQ run/formal 队列驱动 Judge 真实执行，并按可配置间隔轮询本人任务至终态。工具 SHALL 按题目和操作类型分别记录创建、完成、终态、端到端耗时和轮询量，且 MUST NOT 将任务入队等同于运行或判题完成。

#### Scenario: 多道算法题按固定规则分担负载

- **WHEN** 多个认证 VU 在配置的多道算法题上执行运行或提交
- **THEN** 每道题按照固定分配规则获得负载，结果可以按题目和操作类型拆分，任一题失败不会被其他题的成功掩盖

#### Scenario: Python 运行完成真实判题

- **WHEN** 认证 VU 对初始化算法题调用不计分运行接口
- **THEN** API 创建运行任务并投递 run 队列，Judge 消费并真实执行，工具轮询至终态后记录一个有效运行样本

#### Scenario: Python 正式提交完成真实判题

- **WHEN** 认证 VU 提交初始化算法题的 Python 正式答案
- **THEN** API 保存答案、创建正式任务并投递 formal 队列，Judge 消费并真实执行，工具轮询至终态后记录一个有效提交样本

#### Scenario: 控制首轮异步积压

- **WHEN** 首轮算法场景的 VU 已有一个未终态任务
- **THEN** 该 VU MUST NOT 再创建另一个任务，并继续按固定间隔轮询，避免以失控队列代替稳态判题负载

#### Scenario: 判题未正常结束

- **WHEN** 任务失败、超时或超过配置的等待上限仍未终态
- **THEN** 工具将其计为判题失败并保留诊断信息，MUST NOT 将其纳入成功完成数

### Requirement: 分阶段且可比较的负载执行

每个场景 SHALL 支持健康等待、空闲基线、单用户预跑、预热、阶梯加压、稳定负载、停止提交、异步任务排空和回收观察阶段。用于 JVM 参数对照的实验 MUST 保持镜像、基础数据规模、负载、文件和算法用例一致，并且每轮只改变一个待比较变量。

#### Scenario: 执行一轮基线实验

- **WHEN** 操作者选择一个独立场景和版本化基线配置
- **THEN** 工具按预定阶段执行并记录阶段时间，实际负载和样本规模可从结果中还原

#### Scenario: 比较两个 JVM 配置

- **WHEN** 操作者修改一个 JVM 或运行时参数后运行对照实验
- **THEN** 其他实验输入保持一致，报告明确列出唯一变量；存在其他差异时结果 MUST 标记为不可直接比较

### Requirement: 同步采集容器、JVM 与业务指标

压测工具 SHALL 在统一时间线上采集 API/Judge 容器内存、limit、CPU、异常退出状态，可获取的 JVM Heap、GC、线程指标，以及 k6 业务结果；算法场景 SHALL 同时分别采集 RabbitMQ run 与 formal 队列深度。采样 MUST 覆盖压力前、压力中和压力后，采样失败 MUST 被显式记录。

#### Scenario: 采集完整内存时间线

- **WHEN** 任一正式场景开始基线采样并运行至回收观察结束
- **THEN** 结果包含带统一实验 ID 和时间戳的容器/JVM/业务时序数据，可以识别空闲、峰值、稳定和压力后数值

#### Scenario: 观察 Judge 总内存

- **WHEN** Python 判题任务启动运行时或沙箱子进程
- **THEN** Judge 容器内存反映 JVM 与子进程的总体占用，同时保留 JVM 指标以区分堆变化与容器 RSS 变化

### Requirement: 保存安全且可审计的实验结果

每轮实验 SHALL 保存运行配置、镜像/版本、环境信息、场景参数、阶段标记、原始指标、业务汇总和失败信息。提交到仓库的模板和结果 MUST NOT 包含密码、Cookie、JWT、CSRF Token、预签名 URL 或环境密钥；本地生成的大体积结果 MUST 被版本控制忽略。

#### Scenario: 生成实验报告

- **WHEN** 一轮实验结束或被停止条件中止
- **THEN** 工具保存可识别的实验记录和结果完整性状态，汇总有效业务样本、错误率、P95/P99、内存峰值、队列峰值及 OOMKilled/重启情况

### Requirement: 压测范围与生产安全边界

本能力 SHALL 仅针对隔离测试环境中的 API 与 Judge 内存调优实验，MUST NOT 使用 Playwright、修改生产业务契约或自动应用 JVM 调优结果。任何调优建议 MUST 引用可复现实验，且不得将单次短时峰值描述为已验证的生产容量。

#### Scenario: 根据实验提出参数建议

- **WHEN** 操作者准备调整 API 或 Judge 的 JVM/容器配置
- **THEN** 建议引用对应实验 ID、负载和观测结果，并作为独立配置变更接受评审，而不是由压测脚本自动修改生产配置
