## Context

`iven-starter-web` 的全局异常处理器直接采用第一条 Bean Validation 错误的默认消息，因此 DTO 注解中的 `message` 就是 API 返回给调用方的提示。目前 7 个请求 DTO 中有 34 个约束未显式配置消息，其中嵌套判题配置也受影响。现有约束规则本身正确，本次只修正错误提示并补充回归保护。

## Goals / Non-Goals

**Goals:**

- 为所有缺失消息的 API DTO 校验约束提供明确、面向用户的中文提示。
- 必填类提示指出具体字段，数值类提示同时指出字段和有效边界，必要时包含单位。
- 用自动化测试覆盖代表性校验失败响应，并约束后续 DTO 不得省略 `message`。
- 保持既有校验条件、接口契约和响应包装不变。

**Non-Goals:**

- 不修改校验规则、字段名称、接口路径、状态码或响应结构。
- 不修改 `iven-starter-web` 或新增项目级异常处理器。
- 不重写已有 `message`，不处理领域层或应用层业务异常文案。
- 不引入前端修改、数据库迁移或新依赖。

## Decisions

### 在 DTO 注解中显式声明消息

逐个补齐 34 个约束的 `message`，文案使用业务字段名，而非简单暴露 Java 属性名。嵌套 DTO 的提示描述当前字段本身，例如“标准解语言不能为空”，不要求全局异常处理器拼接完整嵌套路径。

不采用全局拦截器自动拼接字段名：该方案难以将属性名稳定翻译成中文业务名称，也无法自然表达毫秒、KB、权重等约束语义，并会改变所有现有接口的消息格式。

### 保持消息粒度与校验注解一致

`@NotNull`、`@NotBlank`、`@NotEmpty` 使用“xxx不能为空”；`@Min`、`@Max`、`@DecimalMin` 使用“xxx必须大于/小于等于N”并视字段语义补充单位。同一字段的必填和范围提示分别配置，避免某条规则触发时仍出现默认消息。

### 使用分层测试验证行为与约定

先添加失败测试，再修改 DTO：

1. 使用 Jakarta Validator 验证各受影响 DTO 的代表性必填、嵌套和边界场景，断言具体消息。
2. 选取现有 Controller 集成测试验证校验失败仍返回 HTTP 400，且 `ResponseMessage.msg` 为显式字段提示。
3. 在现有架构测试体系中加入 DTO 校验消息约定检查，扫描 `api.dto` 下的 Jakarta Validation 约束并要求 `message` 非空白；使用项目已有 ArchUnit 测试依赖，不增加依赖。

## Risks / Trade-offs

- [精确消息断言使后续文案调整需要同步修改测试] → 只对代表性场景断言完整消息，约定测试仅检查消息存在且非空白。
- [静态约定检查可能遗漏注解特殊位置或误扫非请求 DTO] → 覆盖类字段、record 组件及嵌套请求类型，实施时用当前 34 个缺失项验证检查有效性。
- [只补部分约束会留下同类问题] → 以全量约定测试作为完成条件，而非仅依赖人工清单。
- [消息变化可能影响依赖通用文案的调用方] → 该变化正是 issue 要求；保持其他响应字段和成功行为不变，不重写已有消息。
