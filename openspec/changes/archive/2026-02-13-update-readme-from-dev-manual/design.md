## Context

当前项目 README.md 文档与开发手册存在以下不一致：
- 部分核心功能描述不完整（缺少成员模块、引流模块的说明）
- 技术架构图需要更新以更好地展示系统模块关系
- 数据库设计部分缺少 ER 图展示表间关系
- 项目结构描述与实际目录结构有出入

本变更旨在根据 `docs/官网功能与开发手册.md` 的内容，系统性地更新 README.md，使其成为项目的权威入门文档。

## Goals / Non-Goals

**Goals:**
- 同步 README 与开发手册的核心功能描述
- 添加 ER 图展示数据库表关系
- 更新技术架构图，增加登录流程和文件访问流程图
- 完善项目结构描述
- 保持 README 的专业性和可读性

**Non-Goals:**
- 不修改开发手册内容（仅作为参考）
- 不修改实际代码或功能
- 不添加新的功能规格（仅更新现有文档）

## Decisions

### 1. 文档结构采用分层组织
**决策**: 将 README 分为项目简介、核心功能、技术架构、数据库设计、快速开始、文档索引等章节
**理由**: 分层组织便于读者快速定位信息，符合开源项目文档惯例

### 2. 核心功能描述与开发手册保持一致
**决策**: 核心功能部分直接使用开发手册的功能清单内容，仅做格式适配
**理由**: 确保文档一致性，减少维护成本

### 3. ER 图和架构图使用 Mermaid 语法
**决策**: 使用 Mermaid 语法绘制图表，嵌入 Markdown
**理由**: GitHub 原生支持 Mermaid 渲染，无需外部图片依赖

### 4. 保持 README 的独立性
**决策**: README 应该是完整的，不需要读者查阅开发手册才能理解项目
**理由**: README 是项目的门面，应当自成体系

## Risks / Trade-offs

| 风险 | 缓解措施 |
|------|----------|
| 开发手册后续更新导致 README 再次过时 | 在 README 中添加注释提醒维护者同步更新 |
| 图表过于复杂影响可读性 | 使用折叠详情或分开展示，保持主线清晰 |
| 信息冗余（与开发手册重复） | README 侧重概览，开发手册侧重详细设计，定位不同 |

## Migration Plan

**部署步骤**:
1. 备份现有 README.md
2. 根据本设计文档更新 README.md
3. 本地预览检查格式和图表渲染
4. 提交变更并验证 GitHub 渲染效果

**回滚策略**:
- 从备份文件恢复原始 README.md
